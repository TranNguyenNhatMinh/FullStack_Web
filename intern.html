🌐 1.1 HTML – Must Know

Structure, semantics, forms — the skeleton of every webpage.

1

Document Structure Must

🏠 Analogy: HTML page = a house. <html> is the whole house. <head> is the attic (settings, invisible). <body> is the living space (everything users see).
<!DOCTYPE html> <!-- declares HTML5 --> <html lang="en"> <head> <!-- invisible settings --> <meta charset="UTF-8"> <title>My Page</title> </head> <body> <!-- everything visible --> <h1>Hello World!</h1> </body> </html>
💡 Rule: <!DOCTYPE html> must be the very first line — no exceptions.

✏️ Exercise

  1. Create index.html from scratch — type the full skeleton without copy-pasting. Add an h1 with your name.
  2. Remove <!DOCTYPE html> and reload. Check DevTools — browser enters "quirks mode".
  3. Check the browser tab — does it show the title?
2

Meta Tags Must

📦 Analogy: Meta tags are the label on a package — they tell the browser what's inside and how to handle it, without being visible content.
<head> <meta charset="UTF-8"> <!-- supports all languages + emoji --> <meta name="viewport" content="width=device-width, initial-scale=1.0"> <!-- mobile-friendly --> <title>My Awesome Page</title> <!-- browser tab text --> <meta name="description" content="About HTML basics"> <!-- Google preview --> </head>
⚠️ Without viewport meta, your page looks tiny and zoomed-out on mobile. Always include it.

✏️ Exercise

  1. Add all 3 essentials: charset, viewport, title. Change the title and confirm it shows in the tab.
  2. Remove viewport, use DevTools (F12 → Toggle Device Toolbar). See the difference? Add it back.
3

Text & Blocks Must

📦 Analogy: div is a cardboard box (block-level — takes the full row). span is a sticky note (inline — only as wide as its content).
<h1>Main Title (use once)</h1> <h2>Section</h2> <h3>Sub</h3> <!-- h1–h6 hierarchy --> <p>A paragraph. Has spacing above and below.</p> <p>Line one.<br>Line two (same paragraph).</p> <hr> <!-- horizontal divider --> <div>Block container</div> <!-- starts on new line, full width --> <span>Inline</span> in text <!-- stays inline -->
💡 Rule: Use div to group sections. Use span to style a word inside text.

✏️ Exercise

  1. Create a mini blog with h1, two h2s, three p tags, and hr between sections.
  2. Use <span style="color:blue"> to color one word inside a paragraph.
  3. Put two divs side by side? They stack! Put two spans? They sit next to each other. Understand the difference.
4

Links & Images Must

<a href="https://google.com">Go to Google</a> <a href="https://google.com" target="_blank">Open in New Tab</a> <a href="about.html">Local page</a> <a href="#contact">Jump to #contact section</a> <a href="mailto:hi@example.com">Email Me</a> <img src="cat.jpg" alt="A fluffy orange cat"> <!-- always include alt --> <img src="https://placecats.com/300/200" alt="cat"> <!-- Clickable image --> <a href="https://google.com"><img src="logo.png" alt="Go to Google"></a>
⚠️ Never skip alt! It helps screen readers and shows when the image fails to load.

✏️ Exercise

  1. Create 3 links: to Google (new tab), a local file, and a jump to an id on the same page.
  2. Add an image. Break the src on purpose — see how alt text shows up instead.
  3. Make the image clickable by wrapping in an <a> tag.
5

Lists Must

📋 Analogy: ul = shopping list (order doesn't matter — bullets). ol = recipe steps (order matters — numbers).
<ul> <li>Apple</li> <li>Banana</li> </ul> <!-- bullets --> <ol> <li>Boil water</li> <li>Add pasta</li> </ol> <!-- numbers --> <!-- Nested list --> <ul> <li>Fruits <ul><li>Mango</li><li>Grape</li></ul> </li> </ul>

✏️ Exercise

  1. Make a ul of 5 favourite movies, ol of steps to make coffee.
  2. Create a nested list: Programming Languages → (JavaScript → Node/React, Python → Django/Flask).
  3. Build a nav using ul + li + a. This is how real navbars are structured.
6

Form Basics Must

📮 Analogy: A form is an envelope. action = where to mail it. method = POST (hand-deliver, hidden) vs GET (postcard, data visible in URL).
<form action="/submit" method="post"> <label for="name">Name:</label> <!-- for + id links label to input --> <input type="text" id="name" name="name"> <button type="submit">Send</button> </form> <!-- GET: for search (data in URL, bookmarkable) POST: for login/signup (data hidden in request body) -->

✏️ Exercise

  1. Build a login form with username + password fields. Use method="post".
  2. Build a search form with method="get". Submit it — watch the URL change to show your query.
  3. Click a label — does it focus the input? That's the for/id connection working.
7

Input Types Must

<input type="text" placeholder="Your name"> <input type="password" placeholder="••••••"> <input type="email" placeholder="you@email.com"> <!-- validates format --> <input type="number" min="0" max="100"> <input type="checkbox" name="agree" value="yes"> I agree <!-- Radio: same name = one group, pick exactly ONE --> <input type="radio" name="size" value="S"> S <input type="radio" name="size" value="M"> M <input type="radio" name="size" value="L"> L
💡 Checkbox vs Radio: Checkboxes = "pick any". Radio = "pick exactly one" (share same name attribute).

✏️ Exercise

  1. Build a registration form: name, email, age (number), password, confirm password.
  2. Add a required "I agree" checkbox with required attribute.
  3. Try submitting an email input with invalid text. Browser validates automatically!
8

Attributes: id vs class Must

🆔 Analogy: id = Social Security Number — unique to one person. class = job title — many people can share the same one.
id — unique
<div id="header">...</div> /* CSS: */ #header { } /* JS: */ getElementById("header") /* link: */ href="#header"
class — reusable
<p class="card">...</p> <p class="card active">...</p> /* CSS: */ .card { } /* multiple classes ok */
<!-- name: key when form is submitted --> <input name="username"> <!-- submits as: username=alice --> <!-- value: submitted value (or default/prefilled) --> <input value="Alice"> <!-- placeholder: ghost text, disappears on type --> <input placeholder="Enter email...">

✏️ Exercise

  1. Create 3 paragraphs sharing class "highlight". Style them all orange. Give one an id="special" — style it gold. See how id overrides class.
  2. Use method="get" and name attributes on inputs. Submit — see how names become URL keys.
9

Buttons Must

<button type="submit">Submit Form</button> <!-- submits the form --> <button type="button">Do Something with JS</button> <!-- does nothing by default --> <button type="reset">Clear Form</button> <!-- clears all fields -->
⚠️ Gotcha! A <button> inside a <form> defaults to type="submit" even without the attribute! Always be explicit.

✏️ Exercise

  1. Form with submit + reset buttons. Fill the form, click Reset. All cleared.
  2. Remove type from a button inside a form. Click it — it submits! Now you know why type matters.
10

Select & Textarea Should

<select name="country"> <option value="">-- Choose --</option> <option value="vn">Vietnam</option> <option value="us" selected>United States</option> </select> <!-- Note: textarea is NOT self-closing! --> <textarea name="msg" rows="5" placeholder="Message..."></textarea>

✏️ Exercise

  1. Build a Contact form with name, email, subject (select), message (textarea 6 rows).
  2. Note: select sends the value attribute, not the display text — test with GET method.
11

Tables Should

📊 Analogy: A table = a spreadsheet. tr = row. td = data cell. th = header cell (bold, centered). thead/tbody = organizational wrappers.
<table border="1"> <thead> <tr><th>Name</th><th>Age</th></tr> </thead> <tbody> <tr><td>Alice</td><td>25</td></tr> <tr><td colspan="2">Merged 2 columns</td></tr> </tbody> </table>

✏️ Exercise

  1. Create a table of 5 movies: Title | Year | Genre | Rating. Use thead/tbody properly.
  2. Add a bottom row with colspan="3" for "Average Rating:", leaving one cell for the number.
12

Semantic HTML Should

🏛️ Analogy: Semantic tags are labeled rooms. div = just "room". header = lobby, nav = directory, main = main hall, section = conference room, footer = exit sign. Same layout — but now browsers, SEO bots, and screen readers understand it.
<header> <h1>My Website</h1> <nav><ul><li><a href="/">Home</a></li></ul></nav> </header> <main> <section><h2>About</h2><p>...</p></section> <article><h2>Blog Post</h2><p>...</p></article> </main> <footer><p>&copy; 2024</p></footer>
💡 Why it matters: Better SEO, accessibility for screen readers, and readable code for teammates.

✏️ Exercise

  1. Take a page built with only divs. Refactor using header, nav, main, section, footer.
  2. Build a blog layout: header + nav, main with 2 articles, aside sidebar, footer.
13

Data Attributes Nice

🗂️ Analogy: Data attributes are sticky notes on HTML elements — invisible to the user but readable by JavaScript.
<button data-action="delete" data-id="42">Delete</button> // In JavaScript — data-user-id → dataset.userId (camelCase) const btn = document.querySelector("button"); btn.dataset.action; // "delete" btn.dataset.id; // "42"

✏️ Exercise

  1. Create 3 product li items with data-id, data-price, data-category.
  2. Add a button in each. On click, read data-id and alert "Added product #[id]!"

🎨 1.2 CSS – Must Know

Styling, layout, flexbox, responsive design — from selectors to media queries.

1

Adding CSS Must

👗 Analogy: Inline = one custom outfit. Internal <style> = dress code for one building. External .css = company-wide dress code across all pages.
/* 1. Inline — one element only */ <p style="color:red">Red</p> /* 2. Internal — all elements on this page */ <style> p { color: blue; } </style> /* 3. External — best for real projects */ <link rel="stylesheet" href="styles.css"> /* Priority: Inline > Internal > External */
💡 Always put * { box-sizing: border-box; margin: 0; padding: 0; } at the top of every CSS file — the universal reset.

✏️ Exercise

  1. Create index.html + styles.css. Link them. Add a rule making h1 blue.
  2. Add inline style (color: red) on a p. Also add CSS rule (color: green). Which wins? Why?
2

Selectors Must

🎯 Analogy: Element = target everyone in a blue shirt. Class = target everyone with a VIP badge. ID = target exactly one person with a unique ID card.
p { color: gray; } /* all <p> */ .highlight { background: yellow; } /* class */ #header { background: navy; } /* id (unique) */ p.highlight { ... } /* p with class "highlight" */ div, p, span { ... } /* multiple elements */ div p { ... } /* p inside div (descendant) */ div > p { ... } /* direct child p of div */ /* Specificity: ID(100) > Class(10) > Element(1) */

✏️ Exercise

  1. 4 paragraphs — element selector makes all gray, class="special" makes 2 red. See class override element.
  2. Give one paragraph id="unique" with gold background — see id win over class.
  3. Descendant selector: .box p { color: red } — only affects p inside .box divs.
3

Box Model Must

📦 Analogy: Shipping a fragile item. Content = the item. Padding = bubble wrap (inside). Border = cardboard walls. Margin = space between boxes on the shelf.
Content
Margin (outside)
Border
Padding (inside)
Content
.box { width: 300px; height: 200px; padding: 20px; /* all sides */ padding: 10px 20px; /* top/bottom left/right */ margin: 0 auto; /* center horizontally! */ border: 2px solid black; border-radius: 8px; box-sizing: border-box; /* padding included in width */ }
⚠️ Default: padding ADDS to width. 300px + 20px padding = 340px wide! Fix: * { box-sizing: border-box }

✏️ Exercise

  1. Create a div (200px wide, 20px padding). Without box-sizing, check rendered width in DevTools. With box-sizing, check again.
  2. Center a fixed-width div with margin: 0 auto. This is one of the most used CSS patterns ever.
4

Colors & Text Must

body { font-family: 'Segoe UI', Arial, sans-serif; /* stack of fallbacks */ font-size: 16px; color: #333; background-color: #f9f9f9; } h1 { font-size: 2rem; /* 2x base = 32px */ font-weight: 700; text-align: center; text-decoration: none; line-height: 1.5; letter-spacing: 1px; } /* Color formats: */ color: red; /* named */ color: #ff0000; /* hex (most common) */ color: rgb(255, 0, 0); /* RGB */ color: rgba(255,0,0,0.5);/* RGB + opacity 0-1 */

✏️ Exercise

  1. Set a base font-family on body. Style h1–h3 with different rem sizes.
  2. Import a Google Font (Poppins), apply it to the body.
  3. Build a card: white bg, dark text, 1px gray border, 8px border-radius. Fundamental pattern!
5

Display Must

🚦 Analogy: block = takes the whole sidewalk. inline = squeezes next to others (can't set width/height). inline-block = stays in row AND respects width/height. none = disappears completely.
display: block; /* full width, new line (div, p, h1) */ display: inline; /* content width only, no w/h control */ display: inline-block; /* inline + respects width/height */ display: none; /* hidden, removed from layout */ visibility: hidden; /* hidden BUT space is kept */

✏️ Exercise

  1. 3 spans: normally side-by-side. Add display:block — they stack. Try inline-block + width — side by side with size.
  2. Build a horizontal nav bar using ul + li with display: inline-block.
  3. Create a modal div with class="hidden" (display:none). Button toggles the class to show/hide it.
6

Flexbox Must

📏 Analogy: Flexbox is a rubber-band container. justify-content = how to distribute children along the main axis (horizontal by default). align-items = how to align them on the cross axis (vertical by default).
.container { display: flex; justify-content: flex-start; /* left (default) */ justify-content: center; /* center horizontally */ justify-content: space-between;/* max space between */ align-items: center; /* center vertically */ align-items: flex-start; /* top */ flex-direction: row; /* default: left→right */ flex-direction: column; /* top→bottom (axes SWAP!) */ flex-wrap: wrap; /* allow multi-line */ gap: 16px; /* space between items */ } .item { flex: 1; } /* grow equally to fill space */ /* ⭐ The most used pattern — center anything: */ .center { display:flex; justify-content:center; align-items:center; height:100vh; }
💡 Remember: When flex-direction is column, justify-content becomes vertical and align-items becomes horizontal — they swap!

✏️ Exercise

  1. 5 colored boxes in a flex container. Try every justify-content value one by one.
  2. Give parent fixed height. Try every align-items value.
  3. Center a 200×200px div perfectly on screen with flexbox on the body.
  4. Navbar: logo left, links right using justify-content: space-between.
  5. 3-column card layout with flex-wrap: wrap and flex: 1 1 250px. Auto-wraps on mobile!
7

Grid Should

🗺️ Analogy: Flexbox = one row/column (1D). Grid = rows AND columns (2D, like a spreadsheet). Use Flex for navbars. Use Grid for page layouts and galleries.
.grid { display: grid; grid-template-columns: repeat(3, 1fr); /* 3 equal cols */ grid-template-columns: 250px 1fr; /* sidebar + main */ grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); /* responsive! */ gap: 16px; } .hero { grid-column: 1 / -1; } /* span ALL columns */

✏️ Exercise

  1. Photo gallery: 9 items, repeat(3, 1fr), gap 12px.
  2. Page layout: header (full), sidebar+main, footer (full) using grid + grid-column: 1/-1.
  3. Responsive gallery with one line: repeat(auto-fit, minmax(200px, 1fr)). Resize window — magic!
8

Position Should

🗺️ Analogy: static = normal flow. relative = shifted from your normal spot (original space reserved). absolute = escaped flow, positioned to nearest positioned ancestor. fixed = glued to the browser window, doesn't scroll.
.relative { position: relative; top: 20px; left: 10px; } /* Absolute inside relative parent: */ .parent { position: relative; } .badge { position: absolute; top: 8px; right: 8px; } /* Sticky navbar: */ .navbar { position: fixed; top: 0; left: 0; right: 0; z-index: 100; }
💡 Key trick: For absolute positioning to work, the parent MUST be position: relative.

✏️ Exercise

  1. Card with a "NEW" badge: card = position:relative, badge = position:absolute; top:8px; right:8px.
  2. Fixed navbar: stays at top as you scroll. Add body padding-top so content doesn't hide behind it.
  3. Modal overlay: position:fixed; top:0; left:0; width:100%; height:100%; background:rgba(0,0,0,0.5).
9

Responsive Design Should

📱 Analogy: Media queries are a wardrobe that changes by weather. Hot day (big screen) = short sleeves (3 cols). Cold day (small screen) = coat (1 col, bigger text).
/* Mobile-first: write base styles for mobile, add @media for larger */ .grid { grid-template-columns: 1fr; } /* mobile: 1 col */ @media (min-width: 768px) { /* tablet+ */ .grid { grid-template-columns: 1fr 1fr; } } @media (min-width: 1024px) { /* desktop+ */ .grid { grid-template-columns: repeat(3, 1fr); } .container { max-width: 1200px; margin: 0 auto; } } @media (max-width: 768px) { /* desktop-first alternative */ .sidebar { display: none; } .nav { flex-direction: column; } }

✏️ Exercise

  1. 3-col cards. Add media query switching to 1 col on mobile. Test with DevTools.
  2. Nav: horizontal on desktop, stacked on mobile (flex-direction: column inside media query).
  3. Build a 2-col layout (sidebar + content) that stacks on mobile. Most common real-world pattern.
10

Pseudo-classes Nice

button:hover { background: darkblue; cursor: pointer; } a:hover { color: purple; text-decoration: underline; } input:focus { outline: 2px solid blue; border-color: blue; } tr:nth-child(even) { background: #f2f2f2; } /* zebra rows */ li:first-child { color: red; } li:last-child { color: blue; }

✏️ Exercise

  1. Style 3 buttons with :hover — change background. Always add cursor: pointer.
  2. Style inputs: gray border default, blue border on :focus. Replace browser default outline.
  3. Zebra-stripe table using tr:nth-child(even).
11

Transitions Nice

/* Put transition on the BASE state — animates both in AND out */ button { background: blue; transition: background 0.3s ease; /* property duration timing */ } button:hover { background: darkblue; } /* now it smoothly animates */ .card { transition: transform 0.2s ease, box-shadow 0.2s ease; } .card:hover { transform: translateY(-4px); box-shadow: 0 12px 24px rgba(0,0,0,0.15); }
💡 Rule: Always put transition on the base state, not :hover — so animation plays on hover-in AND hover-out.

✏️ Exercise

  1. Button with background color transition. Try 0.1s (snappy), 0.5s (smooth), 1s (slow).
  2. Card "lift" effect: transition transform + box-shadow on hover.
  3. Nav link with bottom border on hover: start with border-bottom: 2px solid transparent, change color on :hover.

⚡ 1.3 JavaScript – Must Know

The highest priority section. Variables to DOM manipulation to async fetch.

1

Variables Must

🗃️ Analogy: const = locked box (can't swap contents). let = unlocked box (can swap). var = old leaky box that causes bugs — avoid.
const name = "Alice"; // can't reassign — use for fixed values let score = 0; // can reassign — use when value changes score = 10; // ✅ // name = "Bob" // ❌ TypeError var old = "avoid"; // ❌ old way — don't use
💡 Rule: Always use const by default. Switch to let only when you know the value will change. Never use var.

✏️ Exercise

  1. Declare const name + let age. Log both. Try reassigning const — read the error.
  2. Counter: let count = 0. Increment 5 times. Log after each.
  3. const object: const user = { name:"Alice" }. Try user.name = "Bob" — it works! Const prevents reassigning the variable, not mutating the object.
2

Data Types Must

const str = "hello"; // string const tmpl = `Hello ${str}!`; // template literal — embed with ${} const num = 42; // number (int + float combined) const bool = true; // boolean let empty = null; // null — intentionally empty (you set it) let undef; // undefined — JS sets it if unassigned typeof "hi" // "string" typeof 42 // "number" typeof null // "object" ← famous JS bug, just know it

✏️ Exercise

  1. One variable of each type. Use typeof on each.
  2. Template literal: `My name is ${name}, I'm ${age} from ${city}.`
  3. Access a missing property on an object → undefined. Access property on undefined → Error! Common bug to know.
3

Operators Must

// Arithmetic 10 + 3 // 13 10 - 3 // 7 10 * 3 // 30 10 / 3 // 3.33 10 % 3 // 1 (remainder — great for even/odd) // Comparison — always returns boolean 5 === 5 // true — strict equal (same value AND type) ← always use this 5 !== 3 // true — strict not equal 5 == "5" // true — loose (type coercion) ← AVOID 5 > 3 // true 5 < 3 // false // Logical true && false // false — AND true || false // true — OR !true // false — NOT const port = env.PORT || 3000; // fallback pattern — use everywhere
⚠️ Always use === never ==. Loose equality causes bugs: "5" == 5 is true, "5" === 5 is false.
4

Conditions Must

if (score >= 90) { console.log("A"); } else if (score >= 70) { console.log("C"); } else { console.log("Fail"); } // Ternary: condition ? "if true" : "if false" const label = isLoggedIn ? "Logout" : "Login"; // Falsy values (act like false): false, 0, "", null, undefined, NaN // Truthy surprises: "0", [], {} are ALL truthy!

✏️ Exercise

  1. Grade calculator: A(90+)/B(80+)/C(70+)/D(60+)/F with if/else if/else.
  2. Rewrite pass/fail as ternary.
  3. Test falsy: log each of 0, "", null, undefined, "0", [], {} in an if. Which ones run?
5

Loops Must

for (let i = 0; i < 5; i++) { console.log(i); } // 0,1,2,3,4 let count = 0; while (count < 3) { count++; } // always update — avoid infinite loop! const fruits = ["apple", "banana"]; for (const fruit of fruits) { console.log(fruit); } // cleanest for arrays

✏️ Exercise

  1. Print 1-10 with for. Then only even numbers (i % 2 === 0).
  2. FizzBuzz 1-30: "Fizz" for ÷3, "Buzz" for ÷5, "FizzBuzz" for both.
  3. Loop over array of 5 names, log "Hello, [name]!" for each.
6

Functions Must

// Declaration (hoisted) function greet(name) { return `Hello, ${name}!`; } // Arrow functions (modern) const add = (a, b) => a + b; // implicit return (single expression) const square = n => n * n; // single param, no parens needed const sayHi = () => console.log("Hi");// no params const multi = (a, b) => { return a * b; }; // body needs return // Default parameters function greet(name, role = "guest") { return `${name} (${role})`; }

✏️ Exercise

  1. Write celsiusToFahrenheit(c): (c × 9/5) + 32. Test 0°C→32°F, 100°C→212°F.
  2. Rewrite as arrow function.
  3. Write sum(numbers) that takes an array and returns the total.
7

Arrays Must

const nums = [1, 2, 3, 4, 5]; nums[0]; // 1 (first) nums.push(6); // add to end → [1,2,3,4,5,6] nums.pop(); // remove from end // Non-mutating — return NEW array: nums.map(n => n * 2); // [2,4,6,8,10] — transform each nums.filter(n => n % 2 === 0); // [2,4] — keep if true nums.find(n => n > 3); // 4 — first match nums.forEach(n => console.log(n));// run for each, returns nothing nums.includes(3); // true nums.join(", "); // "1, 2, 3, 4, 5"
💡 map vs forEach: Use map when you want a NEW array. Use forEach when you just want to DO something (no return value).

✏️ Exercise

  1. Prices [10,25,8,40,15]: filter over $15, map to apply 10% discount, find first under $10.
  2. Shopping cart: empty array, push items, pop last, log after each step.
  3. Chain: numbers 1-10 → filter odd → map to squares.
8

Objects Must

const user = { name: "Alice", age: 25, address: { city: "Hanoi" } }; user.name; // "Alice" — dot notation user["name"]; // "Alice" — bracket notation const k = "age"; user[k]; // dynamic key access user.email = "a@b.com"; // add key user.age = 26; // update delete user.address; // remove const { name, age } = user; // destructuring — extract to variables Object.keys(user); // ["name", "age"] Object.values(user); // ["Alice", 26]

✏️ Exercise

  1. Product object: name, price, category, inStock. Access each both ways.
  2. describeProduct(p) function that returns a template literal sentence.
  3. Array of 3 product objects. Filter to inStock only. Map to get only names.
9

parseInt / parseFloat Must

🔄 Analogy: Form inputs are always STRINGS. "42" + 1 = "421" (string concat). You must convert first. parseInt/parseFloat do that conversion.
parseInt("25"); // 25 parseInt("25.9"); // 25 — drops decimal parseInt("10px"); // 10 — stops at non-number parseInt("abc"); // NaN parseFloat("3.14"); // 3.14 — keeps decimals Number("42"); // 42 — strict (Number("42px") = NaN) const n = +input; // shorthand for Number(input)

✏️ Exercise

  1. Two number inputs + button. Without parseInt: "2"+"3"="23". With it: 5. See the difference!
  2. Build a temperature converter form. Read with parseFloat, compute, display result.
10

isNaN Must

isNaN(42); // false — valid number isNaN("hello"); // true — can't convert isNaN(NaN); // true // NaN !== NaN — it's the only value not equal to itself! // That's why you need isNaN() — can't do (value === NaN) // Validate user input: const num = parseFloat(input.value); if (isNaN(num)) { alert("Enter a valid number!"); return; } // safe to use num now

✏️ Exercise

  1. Validated number input: read value, check with isNaN, show error or proceed.

DOM – Select Must

🔍 Analogy: The DOM is a live tree of all HTML elements. Selecting elements = searching a filing cabinet. By unique ID, by CSS selector, or grab all matching items at once.
document.getElementById("btn"); // by id (no # symbol) document.querySelector("h1"); // first matching CSS selector document.querySelector(".card"); // by class document.querySelector("#header"); // by id document.querySelector("input[type='email']"); document.querySelectorAll(".card"); // ALL matches (NodeList) allCards.forEach(card => console.log(card)); // loop NodeList
⚠️ querySelector on missing element returns null. Calling methods on null = error. Always check if (element) first.

DOM – Content Must

const el = document.querySelector("#myDiv"); el.innerText = "New text"; // set visible text el.textContent = "New text"; // similar, includes hidden el.innerHTML = "<strong>Bold!</strong>"; // renders HTML ⚠️ XSS risk const input = document.querySelector("#name"); input.value; // get current typed value input.value = ""; // clear input
⚠️ XSS with innerHTML! Never do el.innerHTML = userInput. A user could inject script tags. Use textContent for user-supplied text.

Events Must

Event Object Must

btn.addEventListener("click", (event) => { event.target; // the element that was clicked event.target.id; // its id attribute event.target.value; // its value (for inputs) }); // preventDefault — stop default browser behavior form.addEventListener("submit", (e) => { e.preventDefault(); // stop page reload! // handle with JS instead }); // Event delegation — one listener handles all children document.querySelector("ul").addEventListener("click", (e) => { if (e.target.tagName === "LI") { e.target.classList.toggle("done"); } });
💡 preventDefault is crucial for forms. Without it, submit causes a page reload and you lose all JS state.

📊 1.4 SQL – Must Know

Query databases, retrieve data, create/update/delete records — essential for backend.

1

Core Concepts Must

🗄️ Analogy: Database = filing cabinet. Table = one drawer (Users, Products). Row = one file in that drawer. Column = a specific field on each file (name, age, email).
-- A table looks like a spreadsheet: -- id | name | email | age -- 1 | Alice | alice@example.com | 25 -- 2 | Bob | bob@example.com | 30 -- id = primary key (unique, auto-increment) -- CRUD = Create(INSERT) Read(SELECT) Update(UPDATE) Delete(DELETE)
2

SELECT & WHERE Must

SELECT * FROM users; -- all rows, all cols SELECT name, email FROM users; -- specific cols SELECT * FROM users WHERE id = 1; -- exact match SELECT * FROM users WHERE age > 18; -- comparison SELECT * FROM users WHERE name = 'Alice'; -- string match SELECT * FROM users WHERE name LIKE 'A%'; -- starts with A SELECT * FROM users ORDER BY age ASC; -- sort ascending SELECT * FROM users ORDER BY name DESC; -- sort descending SELECT * FROM users LIMIT 10; -- first 10 rows only
3

INSERT / UPDATE / DELETE Must

INSERT INTO users (name, email, age) VALUES ('Dave', 'dave@test.com', 28); UPDATE users SET age = 29 WHERE id = 4; UPDATE users SET name = 'David', age = 29 WHERE id = 4; DELETE FROM users WHERE id = 4;
⚠️ Always use WHERE with UPDATE and DELETE! Forgetting WHERE updates/deletes ALL rows. DELETE FROM users = entire table gone!
4

Aggregates & JOIN Should

SELECT COUNT(*) FROM users; -- total rows SELECT AVG(age) FROM users; -- average SELECT SUM(price) FROM orders; -- sum SELECT MAX(age), MIN(age) FROM users; -- max and min -- JOIN: combine two tables SELECT users.name, orders.product FROM users JOIN orders ON users.id = orders.user_id; -- Links users.id (primary key) with orders.user_id (foreign key)

✏️ SQL Exercises

  1. Design a "students" table. Write SELECT queries: all, only A students, scores above 80.
  2. INSERT yourself as a student. UPDATE your score. DELETE a student by id.
  3. COUNT all students, AVG score, MAX score.
  4. Practice on sqliteonline.com — free, runs in browser.
  5. Explain CRUD out loud: Create=INSERT, Read=SELECT, Update=UPDATE, Delete=DELETE. Common interview question!

🐘 1.5 PHP – Must Know

Server-side scripting — handle forms, talk to databases, generate dynamic HTML.

1

Syntax & Variables Must

🖥️ Analogy: PHP runs on the SERVER before the page reaches the browser. The browser = customer. PHP = the kitchen. The customer sees the finished plate (HTML). Never sees the kitchen (PHP code).
<!-- PHP goes inside <?php ... ?> --> <?php $name = "Alice"; // variables always start with $ $age = 25; echo "Hello, " . $name; // dot = string concat in PHP echo "<p>Age: {$age}</p>"; // {} embeds vars in double quotes $fruits = ["apple", "banana"]; echo $fruits[0]; // "apple" $user = ["name" => "Alice", "age" => 25]; // associative array (like JS object) echo $user["name"]; // "Alice" if ($age >= 18) { echo "Adult"; } else { echo "Minor"; } foreach ($fruits as $fruit) { echo "<li>{$fruit}</li>"; } ?>

✏️ Exercise

  1. PHP page: declare $name, echo "Hello, [name]!" inside HTML.
  2. Loop over an array with foreach and output each as a <li>.
2

$_GET & $_POST Must

<!-- HTML form submits to process.php --> <form action="process.php" method="post"> <input type="text" name="username"> <button type="submit">Login</button> </form> <!-- process.php --> <?php // $_POST: from method="post" form $username = $_POST["username"]; // $_GET: from URL (?id=5&sort=asc) $id = $_GET["id"]; if ($_SERVER["REQUEST_METHOD"] === "POST") { if (empty($username)) { echo "Username required!"; } else { $safe = htmlspecialchars($username); // sanitize for HTML output echo "Welcome, {$safe}!"; } } ?>

✏️ Exercise

  1. HTML form → process.php. Read and display $_POST values.
  2. Add validation: show error if empty, success message if filled.
  3. Search form (method="get"). Read $_GET — see query in URL.
3

Sessions & DB Connect Should

<?php session_start(); // MUST be called before any output! $_SESSION["user_id"] = 1; // remember across pages if (isset($_SESSION["user_id"])) { echo "Logged in"; } else { header("Location: login.php"); // redirect } session_destroy(); // logout // DB Connection (mysqli) $conn = new mysqli("localhost", "root", "", "mydb"); $result = $conn->query("SELECT * FROM users"); while ($row = $result->fetch_assoc()) { echo $row["name"]; } ?>
⚠️ SQL Injection! NEVER: "SELECT * FROM users WHERE name='$name'". User can type ' OR '1'='1 and get all data. Always use prepared statements: $stmt = $conn->prepare("...WHERE name=?"); $stmt->bind_param("s", $name);

✏️ Exercise

  2. Create a protected page that redirects to login if not logged in.
  3. Logout page: call session_destroy() and redirect to login.

⚛️ 1.6 React – Must Know

Build interactive UIs with components, props, and state. The most popular frontend library.

1

What is React + JSX Must

🧩 Analogy: React is LEGO for UIs. You build small, reusable pieces (components) and snap them together. Each piece can have settings (props) and memory (state). Change one block, only that block updates — not the whole page.
// JSX: HTML-like syntax inside JavaScript — compiles to JS function Hello() { const name = "Alice"; const isLoggedIn = true; return ( <div> <h1>{name}</h1> // {} = any JS expression <p>{2 + 2}</p> // renders "4" <p>{isLoggedIn ? "Welcome!" : "Login"}</p> <div className="card">...</div> // class → className <img src="x.jpg" alt="x" /> // must self-close with /> </div> ); } // JSX differences: class→className, for→htmlFor, style={{color:'red'}}, onclick→onClick
2

Components & Props Must

// Component = function that returns JSX. Name MUST start with UpperCase. function UserCard({ name, age, role }) { // destructure props return ( <div className="card"> <h2>{name}</h2> <p>Age: {age} | Role: {role}</p> </div> ); } function App() { return ( <div> <UserCard name="Alice" age={25} role="Admin" /> <UserCard name="Bob" age={30} role="User" /> </div> ); } // Rendering a list: map() + key prop (required!) const users = [{ id:1, name:"Alice" }, { id:2, name:"Bob" }]; function List() { return <ul>{users.map(u => <li key={u.id}>{u.name}</li>)}</ul>; }
💡 Props are read-only! A component never modifies its own props. Data flows one direction: parent → child. This makes bugs easier to find.
3

useState Must

🧠 Analogy: State = a component's memory. A regular variable forgets its value after every render. State remembers. When state changes, React automatically re-renders — you never touch the DOM manually.
import { useState } from 'react'; function Counter() { // [currentValue, setterFunction] = useState(initialValue) const [count, setCount] = useState(0); return ( <div> <p>Count: {count}</p> <button onClick={() => setCount(count + 1)}>+</button> <button onClick={() => setCount(0)}>Reset</button> </div> ); } // Controlled input — form handling in React function LoginForm() { const [email, setEmail] = useState(""); return ( <form onSubmit{e => { e.preventDefault(); console.log(email); }}> <input type="email" value={email} onChange={e => setEmail(e.target.value)} /> <button>Submit</button> </form> ); }

✏️ React Exercises

  2. Toggle component: button shows/hides a text block. State: boolean.
  3. ProductCard component: accepts name, price, category as props. Render 3 with different data.
  4. Todo list: useState for input value + items array. Add on button click, display all.
  5. Controlled login form: name + email fields, log values on submit. onChange keeps state in sync.

🎨 1.7 Bootstrap – Nice to Know

Pre-built CSS classes for responsive layouts, components, and utilities. Build UIs fast.

1

Grid System Nice

📐 Analogy: Bootstrap divides every row into 12 slices. col-6 = 6 slices (half). col-4 = 4 slices (third). col-md-6 = 6 slices on medium+ screens, full-width on mobile. Free responsive layout with zero CSS!
<!-- Add Bootstrap CDN in <head> --> <link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.0/dist/css/bootstrap.min.css"> <!-- Grid: container → row → col(s) --> <div class="container"> <!-- centered max-width wrapper --> <div class="row"> <div class="col">Equal 1</div> <!-- auto-split --> <div class="col">Equal 2</div> <div class="col-8">Main (8/12)</div> <!-- fixed size --> <div class="col-4">Sidebar</div> <div class="col-12 col-md-6">Responsive card</div> <!-- full on mobile, half on md+ --> <div class="col-12 col-md-6">Responsive card</div> </div> </div>
2

Components & Utilities Nice

<!-- BUTTONS --> <button class="btn btn-primary">Blue</button> <button class="btn btn-danger">Red</button> <button class="btn btn-outline-secondary">Outline</button> <!-- CARD --> <div class="card"> <img src="..." class="card-img-top" alt="..."> <div class="card-body"> <h5 class="card-title">Title</h5> <p class="card-text">Description</p> <a href="#" class="btn btn-primary">Go</a> </div> </div> <!-- FORM --> <input type="text" class="form-control" placeholder="Name"> <select class="form-select">...</select> <!-- UTILITIES: flexbox, spacing, text --> <div class="d-flex justify-content-between align-items-center gap-3">...</div> <!-- Spacing: m=margin p=padding, t/b/s/e/x/y for sides, 1-5 scale --> <div class="mt-3 mb-4 px-2">...</div> <!-- 3=16px 4=24px 2=8px --> <p class="text-center text-muted fw-bold">Styled text</p> <div class="bg-primary text-white p-3 rounded">Blue box</div>
💡 Bootstrap spacing scale: 1=4px, 2=8px, 3=16px, 4=24px, 5=48px. So m-3 = 16px margin all sides.
